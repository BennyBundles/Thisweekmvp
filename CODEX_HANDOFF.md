## Architecture and boundaries

This is a static HTML/JavaScript application deployed by GitHub Pages, with separately deployed Supabase Edge Functions and PostgreSQL objects. There is no root npm build/package manifest; validation uses Node scripts and built-in modules.

| Surface | Source | Responsibility |
|---|---|---|
| Main planner | `index.html` | Browser-local weekly planning, Home/Details, progressive disclosure; no network connections |
| Preview launcher | `preview.html` | Links into public release preview |
| Standalone preview | generated by `prepare-public-preview.mjs` | Separate demo/planning storage; manifest, service worker and icon are separate assets |
| Money Sandbox Lab | `money-lab/index.html`, `app.js` | Authenticated provider preflight and controlled sandbox money workflows |
| Account & Security | `account/` | Recoverable identity, recovery, TOTP, session/account closure; public readiness still false |
| Operations | `ops/` | AAL2 staff dashboard, risk/cases, incidents, monitoring and audited release gates |
| Support | `support/` | Customer requests and messages; cannot initiate refunds or money movement |
| Backend | `supabase/functions/`, `supabase/phase19`–`phase31` | Provider integration, ledger, risk, Auth/session checks, operations and release interlock |
| Release | `.github/workflows/pages.yml`, `prepare-site.mjs` | Deterministic CSP staging, validation, curated artifact, Pages and post-deploy verification |

Planner state: core schema **3**, portable schema **1**, USD integer cents; legacy storage key `thisweek.state.v2` remains intentional. Preview uses `thisweek.publicPreview.state.v2`. Identity surfaces share tab-scoped `thisweek.auth.session.v1` in sessionStorage. A cloud-account closure is distinct from deleting the local plan.

Provider observations and imported activity are not planning transactions until explicitly applied. Available Now and Spendable This Week remain planning calculations, not held funds. Server custody, transfers, holds, settlements and reversals use the separate money ledger.

Plaid supplies external bank linking/data/funding-account integration; Unit supplies deposit/card/ACH infrastructure; Pinwheel supplies deposit switching; Method supplies bill-payment integration. Code and deployed infrastructure do **not** establish provider production approval or completed sandbox execution.

## Strict do-not-break rules

- Preserve the compact Home experience, Details navigation, keyboard/accessibility behavior, reduced motion, iPhone safe areas, and existing financial semantics.
- Do not replace schema/storage keys, reset existing plans, silently import provider activity, or enable portable restore without a reviewed migration and tests.
- Preserve exact CSP hashes from staging, no unsafe-inline relaxation, and separate network allowlists for identity/lab surfaces.
- Never persist Auth tokens in localStorage or store passwords. Reject anonymous identities and revoked sessions for protected server actions; preserve AAL2 requirements.
- Use `app_metadata.thisweek_role` only for staff authorization, never editable user metadata. Keep least privilege.
- Never grant browser roles direct access to server tables/RPCs to fix an access error.
- Signed webhook authentication must precede parsing/processing; keep provider-specific signature and freshness rules. Do not equate `verify_jwt=false` with unauthenticated access.
- Preserve integer-cent balanced journals, atomic balance checks, idempotency and compensating entries. Never edit/delete posted financial history.
- Preserve risk-before-provider ordering, review/deny behavior, strongest user restrictions, and fail-closed card authorization.
- Do not guess an envelope for unmapped credits; retain operations review. Support/disputes must not create speculative payouts.
- Keep live-money flags, independent database release interlock, production risk controls and manual approvals intact. No customer reward promise while the sandbox offer is inactive.
- Keep nonce-authenticated notification dispatch, leases/retries and honest delivery state. Never mark unconfigured delivery as sent.
- No unrelated shared-project changes or destructive rollback of accounting/audit data.
